# Production baseline v1

This is an original synthetic Meercata corpus. It contains no captured user, customer, production, credential, exploit binary, or third-party traffic. All addresses are from the RFC 5737 documentation ranges, all Ethernet addresses are locally administered, and every byte is deterministically generated by `generate.py` under the Meercata license.

The corpus exercises positive detection across DNS, HTTP, raw TCP, and raw UDP plus benign negative DNS, HTTP, and TLS traffic. Positive payloads contain only the minimum inert indicator text needed to exercise the reviewed rules; they do not execute an exploit, connect to a real service, or contain reusable malicious code.

The positive oracle identities were reviewed in the ET/Open ruleset whose SHA-256 is `4ddb3e3e443306f49bf8d5ab9419a696a05455b1056b3f55e546ddb91d398a4e`, built by `suricata-update` 1.3.8 and qualified with Suricata 8.0.6 on 2026-08-15:

- `2032091` — DNS query for `allports.exposed`;
- `2031459` — HTTP request for the SolarWinds `web.config.i18n.ashx` path;
- `2100498` — inert `uid=0(root)` response text;
- `2001597` — Netop protocol identification string.

The pack does not redistribute the ET/Open rule text. A candidate that removes, disables, or incompatibly changes one of these identities fails its positive case. Each positive case also forbids the other three identities, and every benign case forbids all four, detecting unexpected cross-case or false-positive behavior.

Regenerate and verify byte identity with:

```text
python3 generate.py --write
python3 generate.py
```

After any intentional source change, inspect every decoded packet and replay result before updating the reviewed hashes in `generate.py` and `manifest.json`.
